Firebase & GitHub Pages — setup steps

Setup guide for MyChecklist, a shared checklist web app with Google sign-in.

Repo: Sayan216016/MyChecklist
Live app (after deploy): https://sayan216016.github.io/MyChecklist/#/

Prerequisites

  • A Google account (for the Firebase console and for test sign-in)
  • Admin access to the MyChecklist GitHub repo
  • Node.js 20+ installed locally (only needed for local testing or Firebase CLI)

Part 1 — Firebase project

1.1 Create or open the project

  1. Open the Firebase Console.
  2. Add or select a project (e.g. MyChecklist).

1.2 Register a Web app

  1. Project overview → Web (</>) icon.
  2. Nickname: MyChecklist Web.
  3. Do not enable Firebase Hosting (GitHub Pages hosts the site).
  4. Copy the firebaseConfig object shown.

1.3 Update firebase-config.js

  1. Edit firebase-config.js in the repo root.
  2. Replace all YOUR_* placeholders with the copied values.
  3. Verify locally: npm run dev — the sign-in page must not show “Setup required”.

Firebase web API keys are meant to be public. Security comes from the Firestore rules, not from hiding the key. If you are not editing the repo yourself, just send the config values to the project owner.

Part 2 — Authentication (Google)

2.1 Enable Google sign-in

  1. Build → Authentication → Get started (if shown).
  2. Sign-in method → Google → Enable → choose a project support email → Save.

Direct URL: https://console.firebase.google.com/project/YOUR_PROJECT_ID/authentication/providers

2.2 Authorized domains

  1. Authentication → Settings → Authorized domains.
  2. Keep localhost.
  3. Add sayan216016.github.io (hostname only — no https://, no /MyChecklist).
  4. Add any custom domain here too if one is used later.

Part 3 — Firestore

3.1 Create the database

  1. Build → Firestore Database → Create database.
  2. Choose Firestore in Native mode (not MongoDB compatibility).
  3. Pick a region near users (e.g. asia-south1). This cannot be changed later.
  4. Start in Production mode.

3.2 Security rules

  1. Firestore → Rules.
  2. Paste the entire contents of firestore.rules from the repo root (view on GitHub).
  3. Click Publish.

Never leave allow read, write: if true on a public site.

3.3 Indexes

The app needs composite indexes on memberIds + updatedAt and invitedEmails + updatedAt. Either:

  • Console: open the app, and click the index-creation link printed in the browser console error; or
  • CLI: from the repo root run:
npm install -g firebase-tools
firebase login
firebase use YOUR_PROJECT_ID
firebase deploy --only firestore

The CLI deploys both the rules and firestore.indexes.json. Indexes take a few minutes to build.

Part 4 — GitHub & Pages

4.1 Push the code

git add .
git commit -m "Configure Firebase"
git push origin master

Make sure these are included: src/, index.html, package.json, vite.config.js, firebase-config.js, and .github/workflows/deploy-pages.yml.

4.2 Set Pages source to GitHub Actions

  1. Repo Settings → Pages.
  2. Source: select GitHub Actions (not “Deploy from a branch”).
  3. The workflow .github/workflows/deploy-pages.yml builds and publishes dist/ on every push to master.

4.3 Verify

  1. Actions tab → Deploy to GitHub Pages → run is green.
  2. Settings → Pages shows the live URL.
  3. Enforce HTTPS is on.

Part 5 — URLs

The app uses hash routes, so no server rewrite config is needed.

Troubleshooting
